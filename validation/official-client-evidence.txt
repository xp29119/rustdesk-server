Wire definitions and server baseline
-----------------------------------
Official rustdesk-server tag 1.1.16:
  73523b31cfd25d77dee862e6fc9f5e1fb5e485ef
Its pinned hbb_common defines rendezvous.proto, BytesCodec, Encrypt and AddrMangle.
The harness uses only small handwritten protobuf field encoders/parsers, TCP frame
codec, client crypto, and IPv4 address encoding. Assertions compare actual process
responses to protocol contracts, not to a reimplemented server's response object.

hbbs main TCP requires the reviewed Stage 2 optional KeyExchange patch and 1 MiB
frame cap. hbbr remains the original native relay protocol; the harness does NOT
send it an hbbs KeyExchange or claim to have tested real desktop media encryption.

Network caveat established from actual baseline source
-----------------------------------------------------
hbbs rendezvous_server.rs handle_listener2: a source IP in 127/8 is routed to the
text management command handler. hbbr relay_server.rs handle_connection similarly
treats a native TCP loopback source as management. A localhost-only socket test
would therefore exercise the wrong protocol on those two ports. The isolated test
namespace uses non-127 IPv4 aliases on lo and has no external interface or route.

UDP reflection fix oracle
-------------------------
Official baseline intentionally ignores UDP PunchHoleRequest; TCP/WS is the
supported path for that request. Normal UDP RegisterPeer/RegisterPk remain valid.
The regression probes a missing target and a registered target, watches both
possible recipients, and verifies heartbeat afterwards. It does not classify all
UDP packets as forbidden or present blanket UDP silence as success.
